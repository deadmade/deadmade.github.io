## Other false or misleading points in the drawing

- **"containers" as an external source.** The box reads as "your application containers". In the repository the log sources are the stack's own services (collectors, APIs, ES nodes, Kibana, load balancers, log-gen, log-sender). The pipeline logs itself, which includes the collectors feeding their own logs back in (`docker-compose.yml:18-22`).
- **Direct arrows with no load balancers.** containers → collectors, collectors → API, API → Elasticsearch and TUI → API each pass through a load balancer that the drawing leaves out: nginx UDP (`container-log-lb`), nginx HTTP with API-key check and rate limit (`log-forwarding-lb`), and HAProxy (`elastic-lb`). The team names these load balancers as a design goal (`abgabe.json:14`), so leaving them out removes the main point of the ×3/×5 replication.
- **"logs" / "types" arrows.** Both arrows carry logs: container logs and sensor logs, each into its own index. "types" names nothing that is stored (R9).
- **Title text "save the logs and the log types".** Same problem as above. "Through the API" is right in substance but skips the nginx proxy (R11).

## Components or paths the drawing leaves out (up to three)

1. **Sensor-log ingestion path:** `log-gen` (CSV of simulated Arduino readings) → shared volume → `log-sender` → `log-forwarding-lb` `/send_log` → API → sensor index (`log-test`).
2. **Load balancers:** `container-log-lb` (nginx UDP), `log-forwarding-lb` (nginx HTTP, `X-Api-Key` auth, rate limiting), `elastic-lb` (HAProxy over es01-es05).
3. **Kibana + Metricbeat:** Kibana is the main documented log viewer; Metricbeat monitors the stack (`docker-compose.yml:375-399,538-554`; `README_Abgabe:19`).
